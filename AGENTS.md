## Repository Map

A full codemap is available at `codemap.md` in the project root.

Before working on any task, read `codemap.md` to understand:
- Project architecture and entry points
- Directory responsibilities and design patterns
- Data flow and integration points between modules

For deep work on a specific folder, also read that folder's `codemap.md`.

## Commit History

- Use exactly one Unicode gitmoji followed by a lowercase English imperative subject.
- Do not add a colon after the emoji or end the subject with a period.
- Sign every commit with GPG (`git commit -S`). If signing fails, do not create an unsigned commit.
- Stage only files that belong to the change.
- Rewrite published history or force-push only when the user explicitly requests it; use `--force-with-lease`.
